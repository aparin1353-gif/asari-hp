## Part 0. マインドセット（ここが半分）

記事の要点を、浅利俊介の状況に翻訳したもの。**書き方より先にこれ。**

### 0-1. レジュメは職務経歴書ではない。サムネであり広告である

> 履歴書・職務経歴書＝「情報を全て正確に載せる正式書類」
> レジュメ＝「アピールのために取捨選択・装飾された情報媒体」

つまり **不要なこと・都合の悪いことは載せなくていい。順序もアピールしたい順でいい。**
（詐称はダメ。厳選と装飾はOK。）

**あなたの場合の具体的な帰結:**

| これまでの発想 | v2での扱い |
|---|---|
| 職歴を時系列で漏れなく書く | 応募先に刺さる順に並べる。刺さらない経験は削る |
| MHD 1年2ヶ月を説明しないと不誠実 | **説明しない。** 言い訳は書かない（書くほど目立つ） |
| 「〜に携わりました」 | 「〜を転換させた」。主語は自分、動詞は他動詞 |
| 数字がないから曖昧に書く | 数字を取りに行く。無ければ相対表現で断定的に書く |
| 趣味「映画鑑賞 週2本」は私的な話 | **エンタメ応募では立派な資産。** 載せる |

### 0-2. ゴールは「最初のインタビューに呼ばれる」こと。それで120点

オファーではなく、**1本目の面接に呼ばれること**を当面のKPIに置く。
そこに行けて初めてフィードバックが手に入り、面接対策の改善点が見える。
逆に呼ばれない限り、何を直すべきかは永遠にわからない。

→ **面接対策よりレジュメ対策を先にやる。** 英語面接の不安を理由にレジュメを後回しにしない。

### 0-3. 機械（ATS）と人間（5〜10秒）の二正面作戦

企業側は ①ATSで自動フィルタ → ②人が1枚10秒で選別、の2段階で絞る。
だから対策も2つ要る。**この2つは求められるものが違う。**

| | ATS（機械） | 人間（10秒） |
|---|---|---|
| 求めるもの | JDのキーワード一致、機械可読な構造 | 一目でわかる成果、読みやすさ |
| 対策 | JDの語をそのまま使う、単一カラム、標準見出し | 冒頭に成果、数字、太字、1ページ |
| 効く場所 | レジュメPDF、LinkedInの検索ヒット | LinkedInの見出し・写真、レジュメ上3分の1 |

### 0-4. 謙遜とプライドは捨てる

競争相手は「1時間触ったら経験ありと書く」人たち。
一方であなたは**日本人にありがちな過小申告**をしている可能性が高い。

**具体的に捨てるべき謙遜:**
- 「社内表彰2回」を職歴本文に埋めている → **独立した受賞欄に立てる。見出しにも入れる**
- 「営業でした」 → 「LVMH×Diageo合弁の外資酒類メーカーで、競合優位アカウントを転換した」
- 「まだ3ヶ月です」 → 期間は言わない。**やったことを言う**
- コネは使う。リファラルは最強の手段。遠慮する理由がゼロ

### 0-5. 量より質。ただし完璧主義は捨てる

- **Mass Applying はしない。** 質の低い応募を100件送っても弾かれるだけ
- 目標は **応募に対して返信率10%前後**。5%を切ったらレジュメを疑う
- 一方で「完璧になってから応募」は最悪。**今週中にv1を出して5件応募する**
- レジュメは生モノ。ちゃんと機能するまで体感1〜3ヶ月、安定するまで半年かかる前提で始める

### 0-7. レジュメ対策はレジュメのためならず

- レジュメに書いた内容は**そのまま面接で深掘りされる** → レジュメ対策＝面接対策の半分
- 職歴をビジネスインパクトで書こうとすると、**普段の仕事で「なぜやるか/どう測るか」を意識するようになる**
- 「リーダーシップ経験が薄い」「インパクトの数字がない」と気づけたら、**今のSORAMICHIで作りに行ける**。
  辞めてから気づくと補う機会がない

## Part 1. 二正面作戦の全体像

「LinkedInのレジュメ」は実は**2つの別の成果物**。両方いる。

```
① LinkedInプロフィール本体
   役割: リクルーターの検索にヒットする + 10秒で「話してみたい」と思わせる
   読み手: 人間（＋LinkedIn内検索エンジン）
   → Part 2

② レジュメPDF（1ページ）
   役割: 応募時に提出。ATSを突破する
   読み手: 機械（ATS）→ 通過後に人間が10秒
   → Part 3
```

①だけ作って②が無い人が多い。②だけ作って①が空欄の人も多い。**両方やる人はほぼいない＝そこで差がつく。**

## Part 3. レジュメPDF（ATS突破用・1ページ）

LinkedInプロフィールとは別に必要。**応募ボタンを押す先はATSであり、そこを通らないと人間に届かない。**

### 3-1. ATS対策の鉄則

| やる | やらない |
|---|---|
| 単一カラム | 2カラム、サイドバー |
| 標準セクション名（Work Experience / Education / Skills） | 「私の歩み」等の独自見出し |
| PDF（テキスト選択可能なもの） | 画像PDF、スキャン、.pages |
| JDの語をそのままの表記で使う | 言い換え（JDが "CVR" なら "CVR" と書く。"転換率" ではない） |
| 本文にすべての重要情報 | ヘッダー／フッターに連絡先（ATSは読まない） |
| 標準フォント、箇条書き | アイコン、グラフ、テキストボックス、表組みレイアウト |

**確認方法:** 完成したPDFを全選択 → テキストエディタに貼り付け。
**崩れたり欠けたりしたら、ATSも同じように読めていない。**

### 3-2. JDごとの調整（Mass Applyingをしない代わりにやること）

1. JDから**キーワードを15〜20個**抜く（技術語／ドメイン語／ソフトスキル）
2. Summary（職務要約 3〜4行）に上位5語を入れる
3. 職歴の箇条書きを**JD関連度の高い順に並べ替え**る（§0-1: 順序は自由）
4. JDに刺さらない箇条書きは**削る**（1ページに収める強制力になる）
5. Skills欄をJDの語で置換

→ この作業は `/pdf {会社名}` で自動化できる（job-hunterスキル Task 8）。

### 3-3. 在籍期間の表記（レジュメPDFのみ）

LinkedInと違い、レジュメPDFは**年のみ表記が国際的な標準**。

```
Moët Hennessy Diageo K.K. — Field Sales Representative        2025 – 2026
SORAMICHI Inc. — CX Consultant                                2026 – Present
```

嘘ではなく一般的な表記慣行。§0-1「都合の悪いことは書かなくていい」の正当な適用範囲。

### 3-4. セクション順序

```
1. 氏名 / 連絡先 / LinkedIn URL          ← 本文の一番上に。ヘッダーに入れない
2. Summary（3〜4行）                     ← JDキーワードを詰める
3. Work Experience                       ← 直近から。各社3〜5 bullets
4. Skills                                ← JDの語で構成
5. Education                             ← 早稲田 + 映画配給インターン
6. Awards & Certifications               ← 社内表彰2回 / TOEIC 945 / TOPIK 4
7. Languages
```
新卒でない限り Education は下。**Awards を独立させるのは §0-4 の実装。**

## Part 4. 応募の運用

### 4-1. KPI

| 指標 | 目標 | 判断 |
|---|---|---|
| 応募 → 返信・一次面接 | **10%前後** | 対策が効いている |
| 同上 | 5%を下回る | **レジュメを疑う。応募数を増やさない** |
| 同上 | 0〜1% | 無対策と同じ。Part 2-3を作り直す |

記録は簡単なスプレッドシートで十分（応募日／会社／職種／JD URL／レジュメver／結果）。
**フィードバックは基本来ない前提**なので、自分の数字だけが唯一のシグナルになる。

### 4-2. リファラルは最大限使う（§0-4「コネバンザイ」）

- **早稲田SILSの同期・OBOG**は最強の弱い紐帯。外資・エンタメ企業に必ずいる
- 応募する前に、**その会社の中の人を1人探して声をかける**のが順序
- ただし**リファラルがあってもATSをスキップできるだけで、人によるレジュメ審査は必ずある**。
  だから Part 2-3 は結局いる
- 依頼テンプレは job-hunter スキル Task 3（LinkedIn Outreach）

### 4-3. 条件が揃うのを待たない

「英語がまだ」「今の会社に入ったばかり」は応募しない理由にならない。
**今週中に5件出す。** 出さない限りフィードバックはゼロのまま。

## Part 5. フィードバックと更新サイクル

### 5-1. 誰に見せるか（ここを間違えると逆効果）

| 見せるべき | 効果が薄い／有害 |
|---|---|
| 応募先領域で**採用した経験がある**人事・マネージャー | 友人、同僚（優しいので通してしまう） |
| **同じ領域の選考を通過した現職者**（外資エンタメ/コンサル勤務のSILS同期など） | 英語ネイティブだが採用経験のない知人 |
| 業界特化のヘッドハンター | 一般的な就活アドバイザー |

AI添削も有効だが、**最終的に人が見るものなので人のフィードバックが一番強い。**
「ここがダメ」と言われる恥を先に払う（§0-4）。

### 5-2. 更新トリガー

レジュメは生モノ。以下のタイミングで**必ず**更新する。

- 案件が1つ終わったとき（成果と数字が新鮮なうちに書く）
- 四半期に1回（何も無ければ「この四半期、書けることが無かった」という警告として受け取る）
- 「リーダーシップの経験が薄い」「数字が出せる仕事がない」と気づいたとき
  → **今のSORAMICHIで取りに行く。** 辞めてから気づくと手遅れ（§0-7）
